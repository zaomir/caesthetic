# DEC-829: CAESTHETIC Agents satellite

## Контекст
DEC-783 запретил плодить Agents-satellites без отдельного DEC. Основатель запросил публичный репозиторий CAESTHETIC по аналогии с `zaomir/raimovdental` и двустороннее обновление с `grainee-v2`.

`zaomir/raimovdental` уже публичный; тот же visibility принимаем для CAESTHETIC.

## Решение
1. Создать публичный GitHub-репозиторий **`zaomir/caesthetic`** как Cursor Agents project для CAESTHETIC.
2. Production SSOT и deploy остаются на **`zaomir/grainee-v2`** (`site-caesthetic/` → caesthetic.com).
3. Sync **двусторонний**, та же политика что DEC-784: per-file hash vs last state; one-side change wins; true conflict → protected paths prefer grainee, иначе newer mtime (tie → grainee).
4. Канон команды:

```bash
bash scripts/caesthetic/sync-agents-bidirectional.sh --apply --commit --push
```

5. VPS2402 systemd timer запускает сверку каждые 15 секунд: `caesthetic-repo-sync.timer`. Без GitHub Actions. Старый 10-минутный cron удаляется установщиком, чтобы исключить гонку.
6. Из публичного зеркала **исключить**: `site-caesthetic/private/` (чужие бренды), unlisted real score `site-caesthetic/score/aurora-medspa-x7k9m2/`, IG footage binaries.
7. Обязательные cross-project authority-файлы Growth Score, которые не совпадают с glob `docs/ssot/CAESTHETIC*.md`, зеркалятся явно и защищены при конфликте в пользу `grainee-v2`:
   - `docs/ssot/COMPETITIVE_DECISION_ANALYSIS_STANDARD.md`;
   - `docs/ssot/EVIDENCE_AND_IMPACT_STANDARD.md`.
8. `SYNC_MANIFEST.yml`, sync runtime и `.agents-sync-state.json` обязаны сохранять эти пути и их точные hashes, чтобы satellite-only агент не блокировался из-за отсутствующего канона и не мог переопределить global authority из satellite.

## Рассмотренные альтернативы
- **Только README без синка** — отвергнуто: основатель явно просил оба направления как у raimovdental.
- **Private repo** — отвергнуто: первый запрос был «публичный», и raimovdental тоже public.
- **Полный `site-caesthetic/` включая `private/`** — отвергнуто: там Expert Dental / другие бренды, не CAESTHETIC.

## Последствия
### Положительные
- Cursor Mobile/Cloud Agents могут открывать проект `caesthetic` без монорепо.
- Правки в любом из двух репо сходятся cron-ом.

### Отрицательные
- Публичный репо показывает CAESTHETIC SSOT и публичный сайт. Ops-списки аудитории в `docs/ssot/CAESTHETIC*.md` зеркалятся так же, как clinic ops в raimovdental.

### Нейтральные
- Deploy channel не меняется.
