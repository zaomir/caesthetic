TASK task-map-baseline

Priority-treatment visibility is measured from a reproducible geo-grid and the weakest cells have an evidence-backed correction plan.

WHY The baseline defines where discovery fails and prevents unrelated search work from being treated as the first fix.

STEPS

  1. Freeze the priority treatment, city query, grid centre, five-mile radius and named comparison set.
  2. Export the 5×5 baseline and label the cells where the practice falls outside the useful local result set.
  3. Check each weak cell against GBP category, treatment and entity evidence before documenting the corrective action.
  4. Repeat the same grid after the accepted changes and compare like-for-like evidence.

NEEDS

  • Approved priority-treatment list
  • Public GBP and competitor URLs
  • Local geo-grid collection skill

DEPENDENCIES None

WHO CAN DO THIS Local search specialist, with an owner approving the priority treatment and market

COMPLEXITY Medium — one controlled measurement set plus evidence review; coordination rises if entity records conflict.

RISK Changing the profile from one grid snapshot can damage relevance; preserve the query method and require corroborating profile evidence.

DONE WHEN

  • Dated 5×5 export with query, centre, radius and competitors
  • Cell-level issue log
  • Like-for-like post-change export

NEXT ACTION Approve the one priority treatment and exact local query for the baseline.

TASK task-gbp-taxonomy

The public GBP categories and services accurately represent the approved priority treatments without stuffing or unsupported claims.

WHY The geo-grid baseline fixes the comparison method before the GBP taxonomy changes are published.

STEPS

  1. Export the current primary category, secondary categories and service inventory.
  2. Compare that inventory with the approved treatment catalogue and the named local comparison set.
  3. Draft the smallest accurate category and service changes, including owner review for naming and compliance.
  4. Publish accepted changes and capture the live profile state.

NEEDS

  • GBP manager access for the chosen implementer
  • Approved treatment catalogue
  • Owner or compliance approval

DEPENDENCIES task-map-baseline

WHO CAN DO THIS GBP/local search specialist with owner approval

COMPLEXITY Medium — straightforward configuration when access and naming are clean; higher if duplicates or category conflicts emerge.

RISK Unsupported services, keyword stuffing or category churn can reduce trust; use only accurate public treatments and retain a before state.

DONE WHEN

  • Before-and-after GBP category export
  • Live service inventory screenshots
  • Owner approval record

NEXT ACTION Export the current GBP category and service inventory.

TASK task-proof-continuity

The same verifiable clinician proof appears at the high-intent Search-to-Website decision points without adding unsupported claims.

WHY Proof is carried into the corrected treatment taxonomy after the discovery path has a stable destination.

STEPS

  1. Inventory the strongest approved clinician proof already visible on Social.
  2. Map each proof item to the relevant treatment page and public profile destination.
  3. Add attribution, clinician context and a clear next step at the chosen decision points.
  4. Test the mobile journey from discovery to the proof and booking action.

NEEDS

  • Approved proof assets and usage permission
  • Website content access
  • Clinical/compliance review

DEPENDENCIES task-gbp-taxonomy

WHO CAN DO THIS Content strategist and web implementer, with clinician/compliance acceptance

COMPLEXITY Medium to high — requires asset permissions, content adaptation, web changes and cross-surface QA.

RISK Proof can become misleading when context or permission is lost; retain attribution and obtain approval before publication.

DONE WHEN

  • Approved proof inventory
  • Live treatment-page URLs
  • Mobile discovery-to-booking QA screenshots

NEXT ACTION Select the two strongest attributable clinician-proof assets for the priority treatment.
