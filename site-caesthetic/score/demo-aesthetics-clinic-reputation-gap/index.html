TASK task-neutral-review-workflow

Every eligible patient receives the same neutral review invitation through a documented, platform-compliant workflow.

WHY A neutral invitation process addresses the measured recency and velocity gap without prohibited selection.

STEPS

  1. Define the same objective eligibility event for every patient without using sentiment, rating or complaint status.
  2. Choose the permitted invitation channel and write neutral copy that allows any honest feedback.
  3. Configure one universal trigger, suppression rule for duplicate sends and an operational owner.
  4. Audit a disclosed sample for invitation coverage and retain the workflow evidence.

NEEDS

  • Current platform-policy review
  • Practice messaging-system access for the chosen implementer
  • Objective eligible-patient event
  • Privacy/compliance approval

DEPENDENCIES None

WHO CAN DO THIS Practice operations lead with privacy/compliance acceptance

COMPLEXITY Medium — copy is simple, but trigger design, platform rules and unbiased coverage require careful operations work.

RISK Sentiment filtering, incentives or selective routing can become prohibited review gating; use one neutral rule for every eligible patient.

DONE WHEN

  • Approved neutral invitation copy
  • Documented eligibility and suppression rules
  • Sample invitation-coverage audit

NEXT ACTION Approve one objective eligibility event that applies equally to every patient.

TASK task-response-standard

Eligible reviews receive timely, privacy-safe acknowledgement under one owned response standard.

WHY Response ownership follows the invitation standard so one operator can manage both current-review workflows consistently.

STEPS

  1. Define the response owner, daily review check and escalation path for sensitive or negative content.
  2. Create short response patterns that acknowledge feedback without confirming treatment or patient status.
  3. Backfill only the selected recent sample, starting with unresolved negative reviews under privacy review.
  4. Measure response coverage and observable response delay over the next disclosed sample window.

NEEDS

  • GBP response access for the chosen responder
  • Privacy-safe escalation policy
  • Named daily workflow owner

DEPENDENCIES task-neutral-review-workflow

WHO CAN DO THIS Trained reputation responder with practice/privacy escalation support

COMPLEXITY Medium and ongoing — initial standards are bounded, while daily coverage creates continuing operating load.

RISK A response can expose protected or clinical information or become argumentative; prohibit confirmation of patient status and escalate sensitive cases.

DONE WHEN

  • Approved response and escalation guide
  • Named daily owner
  • Dated response-coverage and response-delay sample

NEXT ACTION Name the daily response owner and privacy escalation reviewer.

TASK task-proof-themes

Recurring public feedback themes inform operations and are reflected across surfaces without scripting, prompting for positive sentiment or copying patient claims.

WHY Theme work follows the neutral invitation and response standards so proof continuity never drives selective collection.

STEPS

  1. Code a disclosed review sample by treatment, clinician, process and experience themes without identifying patients.
  2. Separate operational gaps from reusable public proof and send sensitive themes to the internal owner only.
  3. Use aggregate, truthful themes to improve treatment-page questions and clinician education content.
  4. Recheck review depth and Cross-Surface proof continuity using the same rubric.

NEEDS

  • Dated public review sample
  • Privacy-safe theme-coding method
  • Content and clinical/compliance reviewers

DEPENDENCIES task-response-standard

WHO CAN DO THIS Research/content strategist with operations and clinical/compliance acceptance

COMPLEXITY Medium to high — requires consistent coding, privacy review and coordinated content changes across more than one surface.

RISK Cherry-picking positive comments or reproducing identifiable claims would distort evidence; use disclosed samples and aggregate themes only.

DONE WHEN

  • De-identified theme ledger with disclosed sample
  • Approved operational action log
  • Live aggregate-theme content and repeat rubric check

NEXT ACTION Select the first dated review sample and approve the de-identification rules.
